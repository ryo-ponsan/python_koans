# KOANS とは何か／メリット／ロードマップでの位置づけ

## KOANS とは？

- **定義**: 失敗するテスト（RED）から始め、最小の修正でテストを通す（GREEN）ことを繰り返しながら、言語の基礎と TDD 思考を体得するための教材。
- **教材**: `gregmalcolm/python_koans`（Python 版 Koans）。このリポジトリにも `koans/` 配下にテストが並び、`koans.txt` の順序で実行されます。
- **学び方**: テストを読み、失敗出力を手掛かりに 1 箇所だけ直して再実行。複数失敗していても「一度に 1 件」を徹底します。

## 何が身につくか（メリット）

- **テスト読解力**: 期待される振る舞い（仕様）をテストから素早く抽出できる。
- **デバッグ能力**: 失敗メッセージの差分（Expected/Actual）を起点に原因を切り分ける癖がつく。
- **最小差分の修正**: 影響範囲を最小化する直し方（実務の PR に直結）。
- **Python 基礎**: 文字列／コレクション／制御構文／関数／クラス／継承／例外などを網羅。
- **TDD の型**: RED → GREEN の反復と、緑を保つための小さなステップ。

## ロードマップでの位置づけ

- `docs/Loadmap.md` の「1. TDD 基礎」フェーズ、および
  `docs/Roadmap_Monthly_2025-09_to_2026-02.md` の 2025-09 に該当。
- ここで鍛えた「テスト先行・最小修正・失敗から学ぶ」型が、
  後続の Kata（Bowling など）、OOP/デザインパターン、アルゴリズム、
  さらにシステム設計・Capstone までの下地になります。

## このリポジトリでの具体的な進め方

- 実行順は `koans.txt` に定義済み。まずは `about_asserts.py` から。
- 使うコマンド（PowerShell）:

```powershell
pytest koans/about_asserts.py -x
```

- 運用ルール（毎回同じ）

  - 1. 失敗を 1 件だけ出す（`-x`）
  - 2. 最小修正で GREEN
  - 3. `docs/koan_notes.md` に 2 行メモ（気付き／境界・注意）
  - 4. `git commit -m "Koans: {file} green"` で記録

- 全体のチェックリストと日次ルーチンは `docs/koans_todo.md` に記載。

## いつ役に立つか（実務・面接への接続）

- **実務**: 既存テストが落ちたときの切り分け／最小差分修正／回帰の再現・防止。
- **チーム開発**: レビューで「どの振る舞いが保証されているか」をテスト基点で説明。
- **面接**: バグの修正プロセス、仕様の読み取り、テスト駆動の思考を具体例で語れる。
- **AI 活用**: 生成結果を鵜呑みにせず、テストで検証 → 差分で学習サイクルを回せる。

## よくあるつまずきと対処

- `is` と `==` の混同 → オブジェクト同一性 vs 値の等価を区別する。
- ミュータブル（list/dict/set）とイミュータブル（tuple/str）の扱い。
- 例外テスト（`with` 文や `pytest.raises` 相当の読み替え）での期待の表現。
